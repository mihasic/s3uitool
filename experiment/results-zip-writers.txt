In-server peak RSS for GET /download-prefix on the same objects (baseline 71 MiB):

  implementation                                   incompressible   compressible
  buffer-whole-object + push from start()              2911 MiB        710 MiB
  stream per chunk + pull-driven backpressure   ->      989 MiB        778 MiB
  plain GET /download of the same object (no zip)       201 MiB              -

Conclusion: the streaming/backpressure fix removed 2/3 of the peak with no
dependency and no loss of compression. client-zip is leaner still, but only
because it never compresses: on compressible content it ships a 209 MB archive
where DEFLATE ships 0.6 MB — a 341x regression on exactly the content this tool
is most often used to download (logs, JSON, config, source).
